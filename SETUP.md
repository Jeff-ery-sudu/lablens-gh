# LabLens GH — setup guide

This is a deployable prototype for a shared pharmacy-lab revision website. The frontend and serverless functions are included. **Built-in AI and shared saving will not work until the owner configures the services below.** No secret API keys are included in the files.

## Included features
- Home page with five separate lab workspaces.
- Each lab icon opens `/lab.html?lab=...`, a dedicated page filtered to that lab.
- Upload a JPG, PNG or WebP image (up to 5 MB in the browser; the AI endpoint limits encoded payload size).
- Server-side Gemini image analysis and draft explanation + five MCQs.
- Review/edit AI drafts before publishing.
- Shared online library backed by Supabase; published resources appear for every visitor.
- Publisher password checked server-side; visitors can read shared content without the password.
- Mobile-responsive design.

## 1. Publish on Netlify
1. Create a free Netlify account at https://www.netlify.com/.
2. Put the contents of this folder in a GitHub repository, or deploy the folder with Netlify's supported deployment workflow. For ongoing updates and serverless functions, connecting a Git repository is recommended.
3. Make sure `netlify.toml` and the `netlify/functions` folder are included.
4. Deploy. Static pages will load, but the AI/shared library will show setup messages until environment variables are set.

## 2. Create shared database/storage on Supabase
1. Create a project at https://supabase.com/ (free tier availability/limits apply).
2. Open the SQL Editor and run:

```sql
create table if not exists public.lab_resources (
  id bigint generated by default as identity primary key,
  lab text not null check (lab in ('pharmacology','technology','natural-drug','biotechnology','chemistry')),
  title text not null,
  summary text not null default '',
  image_url text,
  questions jsonb not null default '[]'::jsonb,
  created_at timestamptz not null default now()
);

alter table public.lab_resources enable row level security;
-- Do not add anon write policies. The Netlify serverless function uses the service-role key.
```
3. In Supabase Storage, create a bucket named `lablens-images` and set it to **public** so classmates can view published image URLs. Do not store patient-identifiable or confidential images.
4. In Project Settings → API, copy the project URL and the **service_role** secret key. Keep the service-role key secret; never put it in HTML/JavaScript or a public Git repository.

## 3. Configure Netlify environment variables
In your Netlify site settings, add these environment variables, then redeploy:

- `SUPABASE_URL` — your Supabase project URL.
- `SUPABASE_SERVICE_ROLE_KEY` — Supabase service-role secret; server-side only.
- `ADMIN_PASSWORD` — create a long, unique password and share only with trusted content editors.
- `GEMINI_API_KEY` — a key from Google AI Studio. API availability, free quotas, and terms may vary by region/account; check them before use.
- `GEMINI_MODEL` — optional; defaults to `gemini-2.5-flash`. Change this to a currently available vision-capable model if needed.

AI key setup: https://aistudio.google.com/app/apikey

The AI key is called only from `netlify/functions/analyze-lab.mjs`, never from the browser. Do not commit keys to GitHub. If a key is accidentally exposed, revoke it immediately.

## 4. How classmates use it
- Share the deployed home page URL.
- Anyone can open a lab page and read published resources.
- AI drafting requires the server-side AI key to be configured.
- Only people with the publisher password can publish to the shared library. The password is entered in the page and sent over HTTPS to the serverless function; share it only with trusted editors.

## Important limits and safety
- This prototype has shared publishing but no individual user accounts, audit log, content moderation queue, or per-user permissions. Treat the publisher password as a temporary small-classroom solution; for a larger public website, add Supabase Auth and stronger moderation/rate limits.
- Anyone who has the publisher password can publish. Rotate it if it is shared too widely.
- AI can misread images or generate incorrect answers. A student/lecturer must verify all content before relying on it for a practical exam.
- Do not upload patient-identifiable, personal, confidential, or restricted course materials.
- Free hosting, AI quotas and storage limits can change; monitor provider terms and usage.
